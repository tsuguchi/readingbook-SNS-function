# 開発環境構築手順（Windows + Docker）

[技術スタック.md](技術スタック.md) で定義した構成を Windows 上の Docker で立ち上げる手順です。すべて PowerShell で実行できます。

---

## 0. 前提

| 項目 | 推奨 |
|---|---|
| OS | Windows 10/11 |
| シェル | PowerShell 7+ |
| Docker | **Docker Desktop**（**WSL2 バックエンド有効**） |
| Git | 最新 |
| エディタ | VS Code（Mermaid / Markdown プレビュー拡張推奨） |

### Docker Desktop の確認

```powershell
docker --version
docker compose version
```

WSL2 が有効になっていることも確認してください（Settings → General → "Use the WSL 2 based engine"）。

> **重要（Windows 高速化のコツ）**: ソースコードは **WSL2 内**（`\\wsl$\Ubuntu\home\<user>\projects\...` 等）に置くと I/O が劇的に速くなります。Windows 側 (`C:\`) からのバインドマウントは遅くなりがちです。

## 2. 環境変数の準備

```powershell
Copy-Item .env.example .env
```

必要に応じて `.env` を編集（パスワード・ポート等）。秘密鍵は後ほど生成して上書きします。

## 3. バックエンド（Rails）ブートストラップ

`rails new` を **使い捨てコンテナ** で実行し、`backend/` ディレクトリ配下に Rails アプリを生成します。

### 3.1 Rails アプリ生成

```powershell
docker compose run --rm --no-deps backend bundle exec rails new . `
  --api `
  --database=postgresql `
  --skip-git `
  --skip-test `
  --force
```

- `--api` … API モード
- `--database=postgresql` … PostgreSQL 採用
- `--skip-test` … 後で RSpec を導入するため標準テストはスキップ
- `--force` … 既存の Gemfile を上書き

### 3.2 Gemfile に必要 gem を追記

`backend/Gemfile` を開き、以下を追記してください。

```ruby
# 認証
gem 'devise'
gem 'devise-jwt'

# 認可
gem 'pundit'

# 検索
gem 'pg_search'

# 非同期ジョブ
gem 'sidekiq'
gem 'redis'

# 画像 / Active Storage
gem 'aws-sdk-s3', require: false
gem 'image_processing'

# シリアライザ
gem 'jsonapi-serializer'

# ページネーション
gem 'pagy'

# プッシュ通知
gem 'fcm'
gem 'webpush'

# CORS
gem 'rack-cors'

# レート制限
gem 'rack-attack'

group :development, :test do
  gem 'rspec-rails'
  gem 'factory_bot_rails'
  gem 'faker'
  gem 'rubocop-rails', require: false
  gem 'rubocop-rspec', require: false
  gem 'dotenv-rails'
  gem 'rswag-specs'
end

group :development do
  gem 'rswag-api'
  gem 'rswag-ui'
end
```

### 3.3 bundle install と DB 設定

```powershell
docker compose build backend
docker compose run --rm backend bundle install
```

`backend/config/database.yml` を以下に置換（`DATABASE_URL` 経由で接続）:

```yaml
default: &default
  adapter: postgresql
  encoding: unicode
  pool: <%= ENV.fetch("RAILS_MAX_THREADS") { 5 } %>
  url: <%= ENV["DATABASE_URL"] %>

development:
  <<: *default

test:
  <<: *default
  url: <%= ENV["DATABASE_URL"]&.sub("_development", "_test") %>

production:
  <<: *default
```

### 3.4 シークレットキー生成

```powershell
docker compose run --rm backend bundle exec rails secret
```

出力された値を `.env` の `SECRET_KEY_BASE` に設定。  
もう一度実行して `DEVISE_JWT_SECRET_KEY` にも別の値を設定。

### 3.5 DB 作成・マイグレーション

```powershell
docker compose run --rm backend bundle exec rails db:create db:migrate
```

## 4. フロントエンド（Next.js）ブートストラップ

`create-next-app` を使い捨てコンテナで実行します。

### 4.1 Next.js アプリ生成

```powershell
docker run --rm -it `
  -v "${PWD}/frontend:/app" `
  -w /app `
  node:22-alpine `
  sh -c "corepack enable && pnpm create next-app@latest . --typescript --tailwind --app --eslint --src-dir --import-alias '@/*' --use-pnpm --no-turbopack"
```

> 対話プロンプトが出たら全てデフォルトで OK。`Tailwind`, `App Router`, `TypeScript`, `src/` ディレクトリ構成が選択されます。

### 4.2 shadcn/ui の初期化

```powershell
docker compose run --rm frontend pnpm dlx shadcn@latest init
```

スタイル選択は `Default`、色は `Slate` 等お好みで。

### 4.3 主要ライブラリの追加

```powershell
docker compose run --rm frontend pnpm add `
  @tanstack/react-query `
  react-hook-form `
  zod `
  @hookform/resolvers `
  ky `
  date-fns `
  lucide-react
```

```powershell
docker compose run --rm frontend pnpm add -D `
  @types/node `
  prettier `
  prettier-plugin-tailwindcss `
  eslint-plugin-tailwindcss `
  vitest `
  @testing-library/react `
  @testing-library/jest-dom
```

### 4.4 ビルド

```powershell
docker compose build frontend
```

## 5. 全サービス起動

```powershell
docker compose up
```

| サービス | URL |
|---|---|
| Next.js（フロントエンド） | http://localhost:3000 |
| Rails API（バックエンド） | http://localhost:3001 |
| MinIO コンソール | http://localhost:9001 （ID/PW: `minioadmin` / `minioadmin`） |
| MinIO API | http://localhost:9000 |
| PostgreSQL | localhost:5432 |
| Redis | localhost:6379 |

バックグラウンド起動:

```powershell
docker compose up -d
```

ログ確認:

```powershell
docker compose logs -f backend
docker compose logs -f frontend
```

停止:

```powershell
docker compose down                    # コンテナ停止・削除
docker compose down -v                 # ボリュームごと削除（DB リセット）
```

## 7. トラブルシューティング

### 7.1 `bundle install` が遅い／失敗する

WSL2 内（`\\wsl$\` 配下）にコードを置いているか確認。Windows 側 (`C:\`) に置くと bind mount が劇的に遅くなります。

### 7.2 `node_modules` が空 / Module not found

`frontend_node_modules` ボリュームが正しくマウントされているか確認:

```powershell
docker compose down -v frontend
docker compose build frontend
docker compose up frontend
```

### 7.3 `entrypoint.sh: not found` / `exec format error`

改行コードが CRLF になっている可能性。`.gitattributes` で `*.sh text eol=lf` を強制しているので、再 checkout すれば解決:

```powershell
git rm --cached -r .
git reset --hard
```

### 7.4 `port is already allocated`

別プロセスがポートを使っています。`.env` でポートを変更:

```env
FRONTEND_PORT=3010
BACKEND_PORT=3011
```

### 7.5 PostgreSQL に繋がらない

ヘルスチェックが通るまで起動を待つ（compose に設定済）。手動確認:

```powershell
docker compose exec postgres psql -U postgres -d readingbook_development -c "\dt"
```

### 7.6 Sidekiq が起動しない

Redis の起動を待つ必要があります。`docker compose logs redis` で確認後、`docker compose restart sidekiq`。

### 7.7 ファイル変更が HMR で反映されない（Windows）

`.env` または `docker-compose.yml` で以下を設定済み（既に有効）:

```
WATCHPACK_POLLING=true
CHOKIDAR_USEPOLLING=true
```

それでも反映されない場合は WSL2 内へコードを移動してください。
